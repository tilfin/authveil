# Google Cloud Identity-Aware Proxy

[English](./google-cloud-iap.md) | [日本語](./google-cloud-iap.ja.md) · [Documentation](./README.md)

Use the `iap` profile when the upstream verifies Google Cloud IAP assertions or reads IAP's authenticated-user headers.

## Configure

Copy the audience expected by your application's IAP resource:

```yaml
identityProxy:
  type: iap
  audience: /projects/123/global/backendServices/456
```

`audience` is required. Optional settings are:

| Key                 | Default                        | Purpose                                             |
| ------------------- | ------------------------------ | --------------------------------------------------- |
| `hostRewrite`       | incoming Host                  | Host sent upstream.                                 |
| `issuer`            | `https://cloud.google.com/iap` | JWT `iss` claim.                                    |
| `identityNamespace` | `accounts.google.com`          | Prefix for authenticated-user ID and email headers. |
| `tokenTtl`          | `10m`                          | Lifetime of the generated assertion.                |

Configure a persistent local key when stable JWKS is needed; see [Signing keys](./configuration.md#signing-keys).

## Generated request

| Header                            | Value                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------ |
| `x-goog-iap-jwt-assertion`        | ES256 JWT with `iss`, `aud`, `iat`, `exp`, identity fields, and custom claims. |
| `x-goog-authenticated-user-id`    | `<identityNamespace>:<subject>`.                                               |
| `x-goog-authenticated-user-email` | `<identityNamespace>:<email>` when the identity has an email.                  |

AuthVeil preserves the incoming Host unless `hostRewrite` is set. It regenerates all `X-Forwarded-*` metadata from the direct request.

## Query parameters and generated responses

The `iap` profile also emulates IAP's special query parameters on any application path:

| Query                             | Behavior                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `gcp-iap-mode=IDENTITY`           | Returns the signed-in identity as JSON with namespaced `email` (when available) and `sub` fields.                        |
| `gcp-iap-mode=CLEAR_LOGIN_COOKIE` | Deletes the local session, expires the session cookie, and redirects to the same URL without the IAP control parameters. |
| `gcp-iap-mode=SECURE_TOKEN_TEST`  | Sends a test assertion upstream according to `iap-secure-token-test-type`.                                               |

The supported secure-token test types are `NOT_SET` (valid token), `FUTURE_ISSUE`, `PAST_EXPIRATION`, `ISSUER`, `AUDIENCE`, and `SIGNATURE`.

Responses generated by the IAP emulation—including authentication redirects, identity responses, cookie-clearing redirects, and rejected WebSocket upgrades—include `X-Goog-IAP-Generated-Response: true`. This lets clients distinguish them from upstream application responses.

## Verify locally

Use the configured audience and AuthVeil's JWKS:

```ts
import { createRemoteJWKSet, jwtVerify } from "jose";

const jwks = createRemoteJWKSet(new URL("http://127.0.0.1:3080/_authveil/.well-known/jwks.json"));

const { payload } = await jwtVerify(assertion, jwks, {
  algorithms: ["ES256"],
  audience: "/projects/123/global/backendServices/456",
  issuer: "https://cloud.google.com/iap",
});
```

The local assertion is not signed by Google. Keep Google key verification in production and use a development-only JWKS override locally. A complete Fastify verifier is in [`examples/fastify-iap`](../../examples/fastify-iap/server.js).
